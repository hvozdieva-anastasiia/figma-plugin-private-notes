Версии новых пакетов выбираются при установке по актуальным стабильным выпускам и проверке совместимости с TypeScript 7 и текущими инструментами. Компилятор не понижается ради несовместимого вспомогательного пакета.

## Обязательные наборы данных

Используем синтетические данные и обезличенные примеры реальных форматов. Тексты частных обсуждений, токены, cookies и точные приватные ссылки не включаются в репозиторий.

| Случай                                               | Ожидаемый результат                               |
| ---------------------------------------------------- | ------------------------------------------------- |
| Три корня и семь ответов                             | Три обсуждения и десять сообщений                 |
| Ответ приходит раньше корня                          | Та же одна ветка, ответ не теряется               |
| Ответ без корня                                      | Неполная ветка с неизвестным статусом             |
| Повтор одной записи                                  | Сообщение и счётчики не удваиваются               |
| Одинаковые имена фреймов с разными ID                | Разные группы                                     |
| Вложенный контейнер в Orders                         | Группа Orders, а не группа внутреннего контейнера |
| GROUP между секцией и внешним фреймом                | Та же внешняя группа                              |
| Самостоятельный INSTANCE                             | Отдельный блок, не произвольный внутренний фрейм  |
| Точки с одинаковыми координатами на разных страницах | Не происходит угадывания страницы                 |
| Узел не найден или чтение завершилось ошибкой        | Ветка видна с правильной причиной                 |
| Совпадение только в ответе                           | Видна вся ветка и место совпадения                |
| Переименование/перемещение контейнера                | Обновлённый контекст без дублирования ветки       |

## Ошибки и гонки

- Ответ файла A пришёл после подключения файла B: в UI остаётся только B.
- Предыдущее поколение расположения не заменяет новое после перемещения узла.
- Два Refresh не создают два независимых набора данных.
- При временном сетевом сбое остаётся корректно подписанный старый снимок.
- При выходе или смене пользователя защищённые данные предыдущего пользователя исчезают.
- 429 удерживает повтор до Retry-After; поиск по памяти работает.
- Неизвестная версия IPC, повреждённый payload и непредусмотренная команда отклоняются.
- Из сообщения UI нельзя открыть посторонний домен или выполнить произвольный JavaScript.
- Переход, который только передал URL, не объявляется подтверждённым раскрытием ветки.

## Авторизация и сервер

Проверяем неверный/повторный state, истёкший процесс, claim без секрета, повторное получение результата, отмену входа и параллельное обновление токенов. Кеш одного пользователя или файла не отдаётся другому. Отозванная наша сессия больше не работает.

Не считаем мокированный OAuth доказательством успешной регистрации приложения. Для команды требуется отдельная настоящая проверка опубликованного приватного OAuth-приложения.

## Browser E2E

Приложение собирается с тестовой реализацией того же порта связи с Figma. Формат её сообщений проверяется теми же схемами; реальный адаптер не содержит веток «если тест — считаем успехом».

Проверяем: подключение → загрузка → поиск → фильтр → раскрытие ответов → запрос нативного перехода → сохранение контекста; дополнительно — пустые результаты, частичная загрузка, недоступная привязка и повторный вход. Playwright перехватывает только ожидаемые запросы и наблюдает UI, а не внутренние переменные React.

Начальный браузер для CI — Chromium. Firefox/WebKit и виртуализация больших списков добавляются при подтверждённой потребности, а не как обязательная стоимость каждого изменения с первого дня.

Автоматический axe-аудит дополняется проверкой клавиатуры, фокуса, читаемых названий и состояний. Он не считается полной проверкой доступности.

## Настоящая Figma перед допуском в пилот

1. URL, построенный из настоящего REST-ответа, раскрывает нужную нативную ветку.
2. Проверены Open, Resolved, отсутствие node ID и переход к корню при наличии ответов.
3. Переход проверен с открытым рабочим UI; поиск и выбранный контекст восстанавливаются.
4. Несоответствие аккаунта внешнего клиента объясняется, а не выглядит как «плагин не работает».
5. Неправильный файл и дубликат файла не выдаются за автоматически проверенное соответствие.
6. Файлы и тексты обсуждений не изменяются плагином.

Такие испытания выполняются на выделенных файлах команды. Не строим обязательный CI на входе в личный Google-аккаунт или на недокументированном доступе к внутренностям Figma.

## Честный статус проверок

Сейчас существуют 15 проверок диагностического URL-стенда; они не означают покрытие продукта. После появления первого модуля отдельная команда его тестов должна требовать непустой набор. Допуск фичи определяется её сценариями приёмки, а не одним общим зелёным запуском или произвольным процентом покрытия.

На этапе 3 настраивается запуск инструментов; тесты функций добавляются вместе с соответствующей реализацией. Фиктивные тесты пустого scaffold не создаются ради отчёта.

Источники: [Playwright: подстановка браузерных API](https://playwright.dev/docs/mock-browser-apis), [Fastify: тестирование запросов](https://fastify.dev/docs/latest/Guides/Testing/).
