# Common Structurizer: согласованные решения

> **Архив прежнего проекта Common Structurizer.** Не является действующим решением Private Notes; актуальные документы: [private-notes-architecture.md](private-notes-architecture.md) и [private-notes-implementation-plan.md](private-notes-implementation-plan.md).

Дата: 11 ноября 2026 года.

## Подтверждено пользователем

- Сначала закрытый пилот, затем выход в Figma Community.
- В закрытом пилоте участвуют люди из одной команды Figma.
- Переход к экрану сам по себе не закрывает задачу: обязательно открытие самой нативной ветки комментария.
- Допустимо открытие в другой вкладке или окне.
- Интерфейс проектируется исходя из пользовательских задач и болей. Количество окон, панелей и экранов заранее не фиксируется.
- Работу выполняем поэтапно, по одному этапу за сессию.

## Задачи, которые должен закрыть интерфейс

Это исходные критерии будущего проектирования, а не согласованный дизайн.

1. Быстро найти обсуждения нужного экрана без ручного поиска по холсту.
2. Понять, какие обсуждения открыты и где остались замечания.
3. Увидеть контекст и ответы, не теряя текущий поиск и выбранное место в списке.
4. Открыть нужную нативную ветку, чтобы продолжить работу в Figma.
5. Понять причину, если комментарий не удалось привязать к экрану или открыть.
6. Отличать отсутствие комментариев от ошибки доступа, неполной загрузки и пустого результата поиска.

При согласовании дизайна сравниваем варианты по числу действий, сохранению контекста и понятности ошибок. Переход в дополнительную вкладку допустим, но не считается самоцелью.

## Согласованный порядок этапов

| Этап                    | Результат                                                                                               |
| ----------------------- | ------------------------------------------------------------------------------------------------------- |
| 1. Техническая проверка | Проверено открытие нативной ветки; установлены ограничения доступа, привязки файла и формата ссылок     |
| 2. Архитектура          | Согласованы границы пилота, правила группировки, компоненты, контракты и критерии приёмки               |
| 3. Тестовое окружение   | Согласованы и настроены дополнительные инструменты, включая Playwright при подтверждённой необходимости |
| 4. Ядро                 | Обработка веток, группировка, поиск и счётчики с тестами                                                |
| 5. Интеграция           | Доступ к Figma, авторизация и загрузка данных                                                           |
| 6. Интерфейс            | Реализованы согласованные сценарии и браузерные проверки                                                |
| 7. Пилот                | Проведены реальные испытания и подготовлен выход в Community                                            |

Это порядок крупных этапов. Если этап требует больше одной сессии, он продолжается; завершение сессии не означает автоматического перехода к следующему этапу.

## Пока не утверждено

- Окончательная архитектура и разбиение компонентов.
- Правило определения экрана в неоднородных Figma-файлах.
- Внешний вид и расположение интерфейса.
- Реализация сервера и способ его размещения.
- Установка новых тестовых зависимостей до этапа согласования.
- Гарантированная работоспособность открытия ветки для всех случаев. Базовая выполнимость на предоставленном комментарии уже подтверждена; границы проверки указаны в протоколе этапа 1.

На этапе 2 подготовлено конкретное предложение «ядро → сценарии → адаптеры → React UI + небольшой backend». Оно изложено в architecture.md, ui-scenarios.md и testing-plan.md и ожидает согласования. Начало этапа 2 не означает автоматического утверждения всех предложенных решений.
