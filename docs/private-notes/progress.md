- `src/plugin/notes-service.ts` — создание (идемпотентное по ID), `update` (текст и/или цель одним JSON), `rebind`, `setStatus`, `remove`. Все изменения идут через один путь `patchNote`. Автор берётся из хоста при каждой команде; в командах автора нет, поэтому чужой ID записи даёт `NOT_FOUND`. `expectedRevision` обязателен; повтор уже применённой команды (хранимая revision ровно на единицу больше и содержит изменение) возвращает сохранённую запись; изменение без отличий не пишет и revision не повышает.
- `src/plugin/current-user.ts` — `readCurrentUserId(figma)`; пустой или отсутствующий ID даёт `null` и `NO_USER`.
- `tsconfig.plugin.json` и `tsconfig.ui.json` включают `src/shared`; общий код собирается без DOM (проверяется программой плагина) и без Figma-глобалей.

### Решения и ограничения

- Существование цели (страница/фрейм в документе) сервис не проверяет: правка текста не блокируется потерянной целью, а проверка новой цели — задача слоя Figma (`figma/targets.ts`, этапы 4–6).
- Повреждённую или записанную более новой версией запись нельзя ни изменить, ни удалить (`CORRUPT` / `UNSUPPORTED_SCHEMA`). Возможность убрать чисто повреждённую запись пользователем — открытый вопрос.
- Повторный `remove` даёт `NOT_FOUND`; UI на этапе 4 должен считать это уже выполненным удалением.
- Неизвестные поля в сохранённой записи при её следующем изменении теряются (в схеме 1 их нет).
- Недоступны или не подключены: сообщения UI, обработчики Plugin Main, шифрование (не согласовано), счётчик 500 записей считает ключи, а не прочитанные записи.

## Этап 6. Разрешение целей, переход и актуальная группировка

Дата: 12 ноября 2026 года. **Статус: выполнен.** В окне плагина появились проверка страниц и фреймов по ID, кнопка «Перейти», актуальные названия и страницы, группа «Без доступной привязки» с перепривязкой.

### Что сделано

- **Протокол:** команды `REFRESH_TARGETS` (до 25 целей, `{type, id}`) и `FOCUS_NOTE` (только `id` заметки; цель берётся из сохранённой записи автора, а не из команды). Состояние цели: `available` (текущее название, настоящая страница), `missing`, `error`; «неизвестно» и «проверяется» хранятся в UI. Новый код ошибки `NAVIGATION_FAILED`.
- **Plugin Main** (`src/plugin/figma/navigation.ts`): `resolveTargets` ищет узлы по ID порциями через `getNodeByIdAsync`, фрейм получает настоящую страницу по цепочке родителей; исключение API даёт `error`, а не `missing`. `focusTarget`: для страницы — `setCurrentPageAsync`; для фрейма — страница, выделение и `scrollAndZoomIntoView`; видимость и блокировка не меняются, окно не закрывается. Для «Весь файл» перехода нет.
- **Группировка и выбор** (`shared/group-notes.ts`, `select-notes.ts`): ключи групп — тип и ID; названия и страница фрейма берутся из ответа Figma, при его отсутствии из снимка в записи; `missing` переносит запись в «Без доступной привязки»; `error`, «неизвестно» и «проверяется» её не переносят; режим «По текущему выбору» использует актуальную страницу фрейма и не показывает потерянные записи; поиск идёт и по актуальным названиям.
- **Интерфейс:** кнопка «Перейти к привязке» (у записей страницы/фрейма), метка «цель не найдена, текст сохранён» и кнопка «Перепривязать» (открывает редактор с выбором другой цели; ID, текст, автор и дата создания сохраняются), «Не удалось проверить привязку» с «Проверить снова». Цели проверяются после загрузки и после изменений только для новых целей; «Обновить» сбрасывает кеш и проверяет заново (поколение запросов отбрасывает запоздалые ответы). Ошибка проверки сама не повторяется, поэтому сбойный API не создаёт цикл. Ненайденная цель при переходе переносит запись в потерянные; ошибка API при переходе — нет.
