- `src/plugin/notes-service.ts` — создание (идемпотентное по ID), `update` (текст и/или цель одним JSON), `rebind`, `setStatus`, `remove`. Все изменения идут через один путь `patchNote`. Автор берётся из хоста при каждой команде; в командах автора нет, поэтому чужой ID записи даёт `NOT_FOUND`. `expectedRevision` обязателен; повтор уже применённой команды (хранимая revision ровно на единицу больше и содержит изменение) возвращает сохранённую запись; изменение без отличий не пишет и revision не повышает.
- `src/plugin/current-user.ts` — `readCurrentUserId(figma)`; пустой или отсутствующий ID даёт `null` и `NO_USER`.
- `tsconfig.plugin.json` и `tsconfig.ui.json` включают `src/shared`; общий код собирается без DOM (проверяется программой плагина) и без Figma-глобалей.

### Решения и ограничения

- Существование цели (страница/фрейм в документе) сервис не проверяет: правка текста не блокируется потерянной целью, а проверка новой цели — задача слоя Figma (`figma/targets.ts`, этапы 4–6).
- Повреждённую или записанную более новой версией запись нельзя ни изменить, ни удалить (`CORRUPT` / `UNSUPPORTED_SCHEMA`). Возможность убрать чисто повреждённую запись пользователем — открытый вопрос.
- Повторный `remove` даёт `NOT_FOUND`; UI на этапе 4 должен считать это уже выполненным удалением.
- Неизвестные поля в сохранённой записи при её следующем изменении теряются (в схеме 1 их нет).
- Недоступны или не подключены: сообщения UI, обработчики Plugin Main, шифрование (не согласовано), счётчик 500 записей считает ключи, а не прочитанные записи.

### Важная находка про Undo

## После этапа 8. Передача и Smart Context

Дата: 12 ноября 2026 года. По решению пользователя; к плановым этапам не относится.

### Что сделано

- **Передача (Selective Handoff):** в панели массовых действий кнопка «Copy as Markdown» копирует выбранные записи как Markdown с тем же порядком, что и список: «Whole file», страницы с их записями, фреймы под страницей, «No available target». Задачи — `- [ ]` / `- [x]`, названия экранируются, имена берутся живые (по ответу Figma), без ответа — сохранённые. Если буфер обмена недоступен, показывается текст для ручного копирования. Чистая функция `notesToMarkdown` (`src/shared/export-markdown.ts`); записи не меняются.
- **Smart Context:** Plugin Main теперь отдаёт «рабочий фрейм» (`focusFrame`): выбранный фрейм либо ближайший фрейм вокруг одного выбранного слоя. «Current selection» включает записи вложенных фреймов на любой глубине (`ancestorFrameIds` в ответе проверки целей), а при отсутствии рабочего фрейма — записи страницы. Строка «Now:» показывает рабочую цель и всегда — сколько записей «здесь» («N notes here»), ничего не скрывая; в режиме «All notes» при рабочем фрейме такие записи подсвечены лёгким фоном и точкой слева (текстовая метка «Here» убрана: её принимали за ссылку; для скринридера добавлен скрытый текст «In the current selection»). Значение по умолчанию для новой записи не изменилось (выбранный фрейм, иначе страница).
- **Запомненный вид:** выбор «All notes / Current selection» запоминается в `figma.clientStorage` (`private-notes:prefs`, только настройка окна, не записи) и применяется при следующем запуске. Команда `SET_PREFS`; `READY` и `REFRESH_NOTES` возвращают `prefs`.
- **Исправление найденной проблемы:** если запомненная высота окна больше, чем показывает Figma, окно обрезается: внизу пропадают массовые действия и ручка изменения размера. Высота теперь ограничена экраном (`screen.availHeight` минус 160), а слишком высокое окно при запуске возвращается в пределы.
