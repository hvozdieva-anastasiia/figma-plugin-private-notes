# Этап 1: открытие нативной ветки

> **Архив прежнего проекта Common Structurizer.** Не является действующим решением Personal Notes & Tasks; проверка перехода к комментариям не доказывает работу личных заметок.

Дата: 11 ноября 2026 года.

Статус: **базовая проверка выполнимости пройдена**. Предоставленная ссылка раскрывает нужную нативную ветку в Chrome и после запуска отдельного локального плагина в Figma Desktop.

## Критерий успеха

В Figma раскрыта конкретная нативная ветка комментария. Простого открытия файла, перемещения к фрейму или видимого пина недостаточно. Другая вкладка или окно допустимы, но их создание не обязательно.

## Фактическое испытание

1. Через MCP подтверждён доступ к указанному фрейму Orders (Light theme).
2. Первое открытие в Chrome потребовало доступ: браузер использовал другой аккаунт. Это не считалось провалом ссылки.
3. Вход под нужным аккаунтом завершён через сохранённую сессию Google. Пароли и коды не вводились, доступы к файлу не менялись.
4. Исходный URL открыт заново без изменений. Раскрылась нативная ветка: автор designer, текст «needs to do mob version», поле ответа и Close comment.
5. Окно ветки закрыто кнопкой Close comment. По состоянию интерфейса подтверждено, что оно закрыто.
6. Та же ссылка открыта в новой вкладке Chrome. Нужная ветка раскрылась повторно без ручного выбора комментария. Подтверждение: Currently expanded comment thread и видимое окно обсуждения.
7. Найдено установленное приложение Figma Desktop 126.11.8. Открыт тот же файл под аккаунтом с доступом.
8. Через Plugins → Development → New plugin создана отдельная локальная регистрация Comment Link Probe с настоящим ID, выданным Figma. Файлы регистрации находятся в исключённой из Git папке work.
9. В эту регистрацию собран стенд из experiments/native-comment-navigation; основные исходники и манифест продукта не заменялись.
10. Стенд запущен из быстрых действий Figma. Исходная ссылка передана через параметр «Ссылка на комментарий», выбрана команда «Открыть скопированную ссылку».
11. Вызов figma.openExternal раскрыл ту же нативную ветку в Figma Desktop: видны нужный текст, Close comment и поле Reply. В этой конфигурации URL обработан внутри приложения; новой вкладки Chrome не возникло.

Комментарии не создавались, не редактировались и не закрывались как решённые. На шаге 5 закрывалось только всплывшее окно. Стенд не изменяет слои дизайна.

## Границы вывода

Наблюдённый формат исходной ссылки: `https://www.figma.com/design/{fileKey}/{fileName}?node-id={nodeId}#{numericId}`. Числовой фрагмент сохранён из предоставленного URL. Другие параметры или форматы в поисках результата не подставлялись.

Результат доказывает выполнимость сценария на предоставленном комментарии. Он не превращает формат URL в официальный контракт и не доказывает корректность сборки ссылки из REST-ответа. Соответствие comment ID, привязки к узлу и URL нужно проверить отдельно на дополнительных данных пилота.

Для этого случая прежнее опасение, что ссылка только приведёт к месту на холсте, не подтвердилось. Описанное поддержкой ограничение остаётся основанием для регрессионных сценариев, а не причиной отрицать наблюдённый успех.

MCP и настоящий плагин имеют разные возможности: внешние URL не поддерживаются в доступном use_figma API, но figma.openExternal успешно выполнен из локального Development-плагина.

## Стенд и автоматические проверки

- Исходники: experiments/native-comment-navigation.
- Сборка реальной отдельной регистрации: `pnpm probe:comment:build --registration work/figma-comment-probe-registration/manifest.json`.
- Тесты URL: `pnpm test:probe`; 15 проверок прошли.
- Проверки типов, линтер, форматирование, все текущие тесты и сборка: `pnpm check`; прошли.
- Автотесты проверяют сохранность URL и отклонение неподходящих адресов. Они не подменяют наблюдение нативного интерфейса.
- Новые тестовые пакеты не устанавливались; использован уже установленный Vitest.

Снимок повторно открытой ветки в Chrome сохранён локально: work/native-comment-navigation/open-thread.jpg. Папка work исключена из Git. Частный URL, снимки и данные авторизации не включаются в исходники стенда.

## Решение по итогам

Техническую возможность открытия нативной ветки можно учитывать при согласовании архитектуры пилота. Переход должен сохранять исходный URL и оставаться отдельным адаптером: поведение зависит от клиента Figma и авторизации.

Операция не должна без проверки обещать «открытие в браузере»: настоящее испытание показало переход внутри Figma Desktop. Сообщение «ссылка передана» не является подтверждением раскрытия ветки; openExternal не возвращает такой результат.

Следующая сессия — согласование архитектуры и правил группировки. Непроверенные случаи остаются явными проверками пилота.
