# Private Notes

Плагин Figma для личных заметок и задач, привязанных ко всему файлу, к странице или к фрейму. Вы видите только свои записи. Записи лежат внутри самого Figma-файла, поэтому ничего не нужно подключать и вводить: плагин открывается и сразу показывает ваши заметки.

Интерфейс плагина только на английском. Документы проекта на русском: [архитектура](docs/private-notes-architecture.md), [план реализации](docs/private-notes-implementation-plan.md), [журнал этапов](docs/private-notes/progress.md), [ручной протокол проверки](docs/private-notes/manual-checks.md).

**Статус: этапы 1–8 плана выполнены; сборка проверена автотестами и вручную в Figma Desktop на одном аккаунте и одном клиенте.** Публикация в Figma Community не выполнялась и не входит в работу без отдельного поручения.

## Установка для разработки

Нужны Node.js 24 и pnpm 11.25.0 (закреплён в `packageManager`). Версии библиотек закреплены в `package.json` и `pnpm-lock.yaml`; не обновлять их при установке.

```powershell
pnpm install --frozen-lockfile
pnpm check
```

`pnpm check` выполняет проверку типов, линтер, проверку форматирования, тесты и сборку. Результат: `dist/code.js` и `dist/index.html` (всё в один файл, без внешних ресурсов). Если pnpm не установлен глобально, `tooling/pnpm.ps1` запускает его из каталога установленного Node.

Подключение в Figma Desktop: **Plugins → Development → Import plugin from manifest…** и выбрать корневой `manifest.json`. Дальше запуск: **Plugins → Development → Private Notes**. Постоянный plugin ID записан в `manifest.json`; менять его нельзя: сохранённые заметки привязаны к ID плагина. Если ID придётся задать заново, `pnpm plugin:id ЧИСЛОВОЙ_ID` (см. `tooling/plugin-id.mjs`).

## Как пользоваться

- **Первая строка окна:** поиск, маленькая кнопка «+» (добавить заметку) и кнопка обновления списка. Ниже фильтры «All / Notes / Open / Done» и переключатель «All notes / Current selection» с кнопкой «Select».
- **Привязка** выбирается в списке «Target» над текстом: выбранный фрейм (по умолчанию, если выделен ровно один фрейм), текущая страница, «Whole file» или «Choose another page or frame…». Выбор фиксируется при открытии редактора и меняется только этим списком: клики по холсту и смена страницы его не трогают. Сохранить можно кнопкой «Save» или Ctrl+Enter; Escape закрывает редактор (если текст набран, спросит подтверждение).
- **Список** один: «Whole file», страницы с их заметками и вложенными фреймами. Группы сворачиваются, в заголовках счётчики (страница считает свои заметки и заметки своих фреймов, без двойного учёта). Названия берутся из Figma, поэтому переименованный или перенесённый на другую страницу фрейм показывается правильно.
- **Задача** отличается от заметки галочкой «выполнено»; выполненная задача не удаляется.
- **Переход:** стрелка у заметки страницы или фрейма переключает страницу и показывает фрейм. У «Whole file» перехода нет.
- **Потерянная цель.** Если страницу или фрейм удалили, заметка уходит в «No available target» вместе с текстом, ничего не стирается и в «Whole file» автоматически не переводится. Кнопка «Rebind» открывает выбор новой цели.
- **Массовые действия:** «Select» включает режим выбора (у заметок и групп появляются чекбоксы). Панель внизу: выбрать все видимые, отметить задачи выполненными или открыть заново, перенести на другую цель, удалить с подтверждением. Каждая заметка меняется отдельно; если часть не удалась, это показано, а неудавшиеся остаются выбранными.
- **Размер окна** меняется ручкой в правом нижнем углу (мышью или стрелками, Shift — крупный шаг) и запоминается для следующего запуска.
- **Обновление.** Список перечитывается кнопкой обновления и при возврате в окно плагина. После Undo или Redo в Figma окно покажет фактическое состояние документа.

## Где хранятся заметки и что это значит для приватности

- Каждая заметка — один ключ `pluginData` на корне Figma-файла (`private_notes_note_<автор>_<id>`). Они сохраняются и синхронизируются вместе с файлом средствами Figma. Отдельной базы, сервера и сети нет (в манифесте сеть запрещена), `clientStorage` хранит только размер окна.
- **Автор определяется автоматически** по `figma.currentUser` в Plugin Main и проверяется на каждом чтении и изменении: по префиксу ключа и по полю внутри записи. Команды окна не содержат автора, поэтому чужую запись через плагин нельзя ни прочитать, ни изменить, ни удалить. Чужие тексты не попадают в ответы плагина окну (это проверяют автотесты).
- **Заметки не зашифрованы.** Обещание такое: плагин не показывает чужие записи. Но `pluginData` документирован как данные плагина, а не как защита содержимого: другой плагин или код с доступом к файлу технически может их прочитать. Не храните в заметках пароли и секреты.
- Плагин ничего не создаёт в файле: ни слоёв, ни комментариев, ни упоминаний, и никому ничего не отправляет. Тексты заметок не пишутся в логи (в коде нет вызовов консоли).
- Для записи нужны права редактирования файла. Режим «только просмотр» не поддерживается.

## Пределы и ограничения

- До 4 000 символов в заметке и 500 заметок на автора в файле; запись не больше 80 кБ (лимит Figma на одно значение — 100 кБ, заметка в 4 000 символов занимает не больше примерно 16 кБ).
- **Undo.** Изменения заметок за один запуск плагина Figma откатывает одним шагом: один Ctrl+Z на холсте может убрать сразу все заметки этой сессии, а Ctrl+Shift+Z вернёт их. Окно после возврата в него показывает фактическое состояние; если вы правили исчезнувшую заметку, оно предложит сохранить её текст как новую.
- Два окна одного пользователя: разные записи независимы; одну и ту же запись одновременно из двух окон атомарно защитить нельзя, но устаревшее изменение не затирает чужое молча, а даёт конфликт.
- Проверены только Figma Desktop, один аккаунт и один клиент. Не проверены: синхронизация между клиентами, второй реальный пользователь, браузерный клиент, файлы с сотнями заметок и фреймов в экземплярах компонентов.
- В выборе другой цели показываются только фреймы верхнего уровня страницы (до 100 по запросу).
- Старые материалы Common Structurizer (`docs/architecture.md`, `implementation-plan.md`, `product-decisions.md`, `ui-scenarios.md`, `testing-plan.md`, эксперимент `native-comment-navigation`) помечены как архив и к Private Notes не относятся.

## Разработка

- `pnpm dev` пересобирает UI и plugin при изменениях; `pnpm build` создаёт `dist/`.
- `pnpm typecheck`: TypeScript 7 (`@typescript/native`) отдельно для UI, Figma sandbox, инструментов и экспериментов. Пакет `typescript` в зависимостях — alias `@typescript/typescript6` только для JavaScript API линтера; не заменять одно другим.
- `pnpm lint`, `pnpm format` / `pnpm format:check`, `pnpm test` / `pnpm test:watch`.
- Структура: `src/shared` (модель, проверки, протокол, группировка и выбор), `src/plugin` (Plugin Main, репозиторий на `figma.root`, сервис заметок, работа с Figma), `src/ui` (React: один reducer, один bridge, компоненты), `tests/private-notes` (тесты), `experiments/private-notes` (стенд API этапа 2, `pnpm probe:notes:build`).
- Skills проекта лежат в `.agents/skills/`; их не меняют при форматировании.
