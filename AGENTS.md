# Private Notes

Рабочая папка: D:\Projects\PrivateNotes. Имя продукта: Private Notes.

Актуальная архитектура: docs/private-notes-architecture.md, версия 4. Актуальный план: docs/private-notes-implementation-plan.md, версия 4. Пользователь согласовал хранение, UI и алгоритм управления записями в обсуждении; открытые технические решения помечены отдельно. Один этап — одна отдельная рабочая сессия.

Этап 1 плана выполнен (см. docs/private-notes/progress.md): окружение восстановлено по lockfile, pnpm check проходит. Постоянный plugin ID получен от Figma и записан в manifest.json (не менять). Импорт манифеста в Figma Desktop подтверждён пользователем. Реализация Private Notes не начата. Следующая рабочая сессия выполняет только этап 2 (реальный стенд API). Не начинать основной UI, backend или криптографию до соответствующих этапов.

Согласованные решения:

- Основная база — pluginData на figma.root, отдельный ключ на запись. Автор определяется и проверяется в Plugin Main. clientStorage для базы, ручные ссылки, fileKey и служебный documentId не нужны.
- Dropdown над редактором выбирает логическую привязку «Весь файл / Страница / Фрейм»; физическое хранение остаётся на корне. Default по выбранному фрейму или текущей странице.
- draftTarget открытого редактора меняется только dropdown; клики по холсту её не изменяют. Сохранение проверяет выбранную цель, а не её совпадение с текущим выделением.
- Один сгруппированный список: записи файла, страницы с прямыми записями и вложенными фреймами; сворачивание, поиск, фильтры, счётчики. Не заменять тремя табами без обсуждения.
- Создание, редактирование, выполнение/возврат задачи, подтверждаемое удаление и перепривязка без смены ID. При потерянной цели текст сохраняется; нет автоматического перевода в «Весь файл».
- Шифрование, источник/восстановление ключа, пароль и экран разблокировки не согласованы. Не считать их реализованными или обязательными; выбор фиксируется отдельно до криптографии. Это не блокирует этап 1.

Документы docs/architecture.md, docs/implementation-plan.md, docs/product-decisions.md, docs/ui-scenarios.md, docs/testing-plan.md и эксперимент native-comment-navigation относятся к прежнему Common Structurizer. Сохранить их как старые материалы; не применять к Private Notes как действующие решения. Проверка перехода к комментариям не доказывает работу личных заметок.

## Инструменты

Node.js 24, pnpm 11; TypeScript 7.0.2 strict; React; Vite для UI; esbuild для Figma sandbox. UI и plugin имеют отдельные типы окружений.

Проверки: pnpm check. Для изолированного эксперимента добавлены 15 тестов обработки ссылки; тестов основной функциональности продукта пока нет. Команда test допускает пустой набор и сама по себе не означает, что поведение продукта проверено.

## TypeScript и линтер

Компилятор tsc поставляется пакетом @typescript/native (alias typescript@7.0.2). Пакет typescript — официальный alias @typescript/typescript6@6.0.2 исключительно для JavaScript API линтера. Не заменять компилятор на TypeScript 6 из-за зависимости typescript-eslint. Схема соответствует рекомендации Microsoft.
